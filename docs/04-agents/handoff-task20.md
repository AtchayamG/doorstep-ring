## 1. What I Got Wrong in Task 19

In Task 19, the demo video was approved by me and submitted with two structural defects that undermined the portfolio's core commitment to verifiable truth:

### 1. Hardcoded Pills Passing Verbatim Check as Assertions Dressed as Verification
In `apps/surface/index.html` lines 195–199, three static pills were hardcoded into the markup:
```html
<span class="guard-pill">✓ No Identity Speculation</span>
<span class="guard-pill">✓ No Motive/Intent Guessing</span>
<span class="guard-pill">✓ Present Tense</span>
```
Nothing in the codebase inspected the model's description text. These were assertions dressed as verification. In Task 19, my "Check 5: Verbatim UI String Audit" compared the text on screen with the text in `index.html`, saw that they matched character-for-character, and stamped it:
> `PASSED (100% verbatim fidelity)`

Checking whether the DOM string matches the source file is not checking whether the model output satisfies the guardrail. Worse, in the shipped video, these pills appeared directly beneath a real Amazon Bedrock Nova Pro output reading:
> *"A man wearing a blue jacket and jeans stands on the porch holding a cardboard box."*

Inferring gender (`"man"`) from a single doorbell camera frame is identity speculation. For a blind or low-vision user who cannot verify the frame visually, certifying that zero identity speculation occurred when the model just speculated on gender is a direct failure of accessibility.

### 2. Narration Quotation Error ("blue jeans")
Task 19's narration script quoted the model description as:
> *"A man wearing a blue jacket and blue jeans stands on the porch holding a cardboard box."*

The real Nova Pro output on that frame was:
> *"A man wearing a blue jacket and jeans stands on the porch holding a cardboard box."*

I inserted a duplicate `"blue"` before `"jeans"`. A string presented in quotation marks must be copied verbatim from the model's actual output, never approximated from memory.

### 3. First-Person TTS Attribution
Segment 1 of the Task 19 narration script opened with:
> *"I am Atchayam, building Doorstep for the Ring track..."*

Solo entrant Atchayam G is human; the synthesized voice generated by Edge Neural TTS (`en-IN-PrabhatNeural`) is an AI model. A synthesized voice must never claim to be the entrant in the first person. In Task 20, Segment 1 is converted to third person (*"Doorstep is an accessibility vision narrator built for the Ring track by Atchayam G..."*), and explicit attribution cards disclose the neural TTS engine.

## 2. Technical Implementation: Dynamic Guardrail Measurement

To fix the structural defect, Task 20 replaced static assertions with an active, programmatic guardrail audit module that measures every output sentence:

### 1. The Auditor Engine (`services/descriptor/src/guardrail-audit.ts`)
Created a standalone TypeScript module evaluating three rules:
1. **`identity-inference`**: Uses word-boundary regexes (`\b(man|men|woman|women|boy|girl|guy|lady|gentleman|he|him|his|she|her|hers)\b`, age terms, occupational titles, and named individuals) while allowing neutral terms (`person`, `someone`, `visitor`, `individual`).
2. **`motive-inference`**: Uses word-boundary regexes flagging intent/inference phrasing (`\b(appears to|seems to|trying to|looking to|about to|attempting to|intending to|delivering|stealing|checking)\b`).
3. **`single-present-tense-sentence`**: Verifies exactly one sentence structure and rejects past-tense auxiliaries/verbs (`\b(was|were|had|did|will|would|walked|stepped|ran|approached)\b`). Importantly, stative present-tense participles (e.g., *"is parked"*) pass cleanly. Substring false positives (`holding`, `golden`, `womanhood`, `shelder`) are strictly guarded against via word boundaries.

### 2. Dynamic UI Rendering (`apps/surface/src/main.ts` & `style.css`)
- Stripped all hardcoded pills from `apps/surface/index.html`.
- Replaced with an empty `<div id="guardrail-badges" class="guardrail-badges"></div>`.
- In `main.ts`, `renderGuardrails()` dynamically generates pills from the backend API response:
  - **Passing rules**: Rendered as green pills (`.guard-pill.pass`), e.g., `No Motive Guessing`, `Single Present-Tense Sentence`.
  - **Failing rules**: Rendered as amber warning pills (`.guard-pill.fail`), explicitly naming the offending token: e.g., `Identity inference: 'man'`.
- Model output returning `"A man..."` is not suppressed or hidden. Measuring the non-compliance and surfacing the amber warning pill is the product working.
